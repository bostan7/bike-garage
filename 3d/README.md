# 3D model — SCOTT Scale 980 (Dark Grey, size L)

The model is **generated by a script**, never edited by hand. Change the numbers or the code, run the build again, and the `.glb` is rebuilt.

```
3d/
├── blender/
│   ├── build_bike.py        ← entry point: builds every part, exports, renders previews
│   ├── compare_photo.py     ← overlays a render on SCOTT's official studio photo
│   ├── build_garage.py      ← entry point for the garage around the bike (see "Garage" below)
│   ├── garagelib/           ← spec.py (all garage sizes) · room.py · props.py · neon.py · textures.py · materials.py
│   └── bikelib/
│       ├── spec.py          ← ALL measurements (official geometry + part sizes)
│       ├── meshkit.py       ← mesh helpers (tubes, revolve, gears, text on surfaces)
│       ├── materials.py     ← colours / PBR materials
│       ├── frame.py · fork.py · wheels.py · brakes.py
│       ├── cockpit.py · drivetrain.py · seat.py
│       ├── accessories.py   ← the 8 acc_* accessories (mudguards, lights, bell, lock, reflectors)
│       └── preview.py       ← studio lights + camera views
├── models/bike.glb          ← the model the app loads (23 named parts + 8 accessories)
├── models/garage.glb        ← the NFS-style night garage (10 named nodes)
├── viewer/                  ← make_viewer.py + template.html: single-file 3D viewer page for review
└── reference/               ← reference material
```

## Build

```bash
"D:/Programs/Blender Foundation/Blender 5.2/blender.exe" --background --factory-startup --python 3d/blender/build_bike.py -- --glb 3d/models/bike.glb
```

Options after `--`:
- `--render DIR`: render preview images into DIR. Views: `side_photo` (same scale and framing as SCOTT's studio photo), `side_nondrive`, `front34`, `rear34`, `front34_nd`, `front`, `top`, `cockpit`, `drivetrain`, `wheel_close`, `tyre_close`, `tread_front`, `tyre_logo`, `cassette_side`, `crank_side`, `head_close`, `fork_close`, `seat_close`, `lever_close`, `caliper_front`, `caliper_rear`, `saddle_close`, `pedal_close`.
- `--views a,b`: render only those views.
- `--blend FILE`: also save a .blend to open in Blender.

Compare with the official photo:

```bash
python 3d/blender/compare_photo.py DIR/side_photo.png OUT_DIR
```

This writes `side_by_side.jpg`, `overlay.jpg` and `edges.jpg` (red = photo, blue = model).

## Garage (`build_garage.py`)
The night garage from the approved web prototype (`design/prototype/template.html`), rebuilt as real geometry.

```bash
"D:/Programs/Blender Foundation/Blender 5.2/blender.exe" --background --factory-startup --python 3d/blender/build_garage.py -- \
    --glb 3d/models/garage.glb --glb-draco android/app/src/main/assets/garage.glb
```
- `--render PNG` (+ `--render-view drive|corner`): one low-res sanity render. Save it outside the repo (renders are not committed).
- The script prints triangles per node (~31k in total, budget 60k) and checks both glb files (nodes present, emissive set).
- Same axes as the bike. Room: x −4.5…+4.5, y −5.6 (front wall, door) … +3.4 (back wall, shutter and sign), height 3.6 m.
  The prototype's three.js coordinates map as three (x, y, z) → Blender (x, −z, y), which is exactly the glTF/Filament frame.
- Textures (concrete floor, concrete blocks, pegboard) are made with numpy at build time (≤ 1024 px, seamless) and embedded as JPEG.
  UVs are box-projected in metres per material (`GPart` in `garagelib/kit.py`). Phone copy: Draco, 16-bit positions, 0.30 MB.

**Node contract** (the app finds these by name; every node is one mesh, origin at the world origin unless noted):

| Node | What | Notes |
|---|---|---|
| `floor` | polished concrete, roughness 0.35, metallic 0 | 3.2 m slabs; saw-cut joints just outside the stripe square |
| `stripes` | yellow/black safety stripes, 2.9 m square (centre line), 90 mm wide | painted, 2 mm above the floor |
| `walls` | concrete block walls on all 4 sides, dark ceiling, 2 steel I-beams, steel door in the front wall | |
| `shutter` | roll-up shutter on the back wall: slats, guide rails, roll box, bottom bar | |
| `props` | pegboard with tools, workbench, tool chest, tyre stack, oil drum, shelving, extinguisher | all > 3 m from the turntable; the tool chest's drawer handles use `neon_yellow` |
| `turntable` | round base, top radius 1.0 m, base 1.04 m | **origin at (0.133, 0, 0)**, top surface z = 0.035 (glTF y = 0.035) |
| `neon_ring` | emissive ring r 0.965 m, half sunk into the turntable edge | origin at (0.133, 0, 0), separate from `turntable` (spin both) |
| `neon_strips` | emissive tubes: base line on all walls + 4 vertical corners | |
| `hex_lights` | hexagon LED grid on the ceiling above the turntable | emissive cool white |
| `sign` | "SCALE 980" (Impact, sheared to italic) on a black plate, back wall | yellow halo layer + yellow-white core |

Emissive materials (glTF `emissiveFactor` + `KHR_materials_emissive_strength`): `neon_yellow` (#D2F500, strength 6),
`led_white` (#E8F2FF, 4), `sign_core` (#F1FF9E, 8). Change them in `garagelib/spec.py`.
Garage nodes carry the extra `garage: <name>` (no `slot`, so they never look like bike parts).

## Review viewer
`python 3d/viewer/make_viewer.py OUT.html` embeds `bike.glb` and the app's part list into one HTML page (rotate, zoom, tap a part).
Models over ~11 MB no longer fit in one page: use `--external`, which writes the model next to the page as base64 text chunks (`bike-glb-N.txt`, for static hosts that don't serve `.glb`). Serve the page with those chunks next to it.
Toni's modifications that are not yet in the app's SeedData are listed in `MODIFICATIONS` in `make_viewer.py`.
The review page is a local review viewer (`3d/viewer/`): rebuild it after each model update.

## Detail and triangle budget (v3)
- Segment counts are scaled by `DETAIL` / `DETAIL_PER_PART` in `bikelib/spec.py` (use `S.seg(part_name, n)` in new code).
- `build_bike.py` prints every part against its v3 budget (`BUDGET`, ~587k in total) and flags parts more than 10 % over.

## Rules
- **One object per part, named exactly like the app's part slot** (`frame`, `fork`, `chain`, …, 23 in total, plus the 8 `acc_*` accessories). Each object also carries `extras: {slot, category}` in the glTF.
- Wheels, tyres, rotors, cassette, crankset, pedals and BB have their **origin on their rotation axis** (axle or BB), so the app can spin them.
- Axes in Blender: +X forward, +Y left (non-drive side), +Z up, ground at z = 0, metres. The glTF export converts to +Y up.
- Positions come from SCOTT's official size-L geometry (`docs/BIKE-SPECS.md`). Derailleur and chain positions were measured on the studio photo (chain on the 10T cog, as photographed).

## v2 (2026-10-05)
